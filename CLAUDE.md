# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Nativra is a source-first UI registry for React Native and Expo, in the style of shadcn/ui. Users run `npx nativra-cli add <item>` to copy TypeScript source into their own project. There is no runtime package. Every item ships two implementations: **NativeWind v4** and plain **StyleSheet**.

This is a pnpm 9 + Turbo monorepo on Node >= 20. Workspaces live in `apps/*`, `packages/*` and `examples/*`.

## Commands

```bash
pnpm install
pnpm build                 # turbo: all packages + docs (docs prebuild also builds the registry)
pnpm typecheck | pnpm lint | pnpm test
node scripts/build-registry.mjs [--pretty]   # registry/ -> dist/registry + mirror into apps/docs/public
pnpm dev                   # docs site on :3000 (predev rebuilds registry)
pnpm --filter @nativra/native-preview sync   # copy StyleSheet components into the Expo preview app
pnpm --filter @nativra/native-preview web    # or android / ios
```

Single package or single test (Vitest):
```bash
pnpm --filter nativra-cli test
pnpm --filter nativra-cli exec vitest run src/transform.test.ts
pnpm --filter nativra-cli exec vitest run -t "test name"
```
The CLI e2e test ([packages/cli/src/e2e.test.ts](packages/cli/src/e2e.test.ts)) runs the built `packages/cli/dist/cli.js` against `dist/registry`. Run `pnpm build` and `node scripts/build-registry.mjs` before it, or it throws.

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs typecheck, lint, build, test, `pnpm audit --audit-level=high`, and a registry build. Pushing a `v*` tag creates a GitHub Release, with notes extracted from `CHANGELOG.md` by `scripts/extract-release-notes.mjs`.

## Architecture

**Registry content: `registry/default/{components,blocks,hooks,templates,themes,utilities}/<id>/`**
- `item.json` holds the metadata: `type`, `status`, `platforms`, `files[]` (each with `path` and an optional `target: nativewind|stylesheet`), `registryDependencies`, `npmDependencies` and `docsPath`. The shape is validated by Zod in `packages/registry-schema`.
- `nativewind/` and `stylesheet/` hold the source. `docs.mdx` holds the docs.
- Source must import through canonical aliases: `@/components/ui`, `@/lib/utils`, `@/hooks`, `@/blocks`. The CLI rewrites these to the consumer's paths ([packages/cli/src/transform.ts](packages/cli/src/transform.ts)), so other import styles won't be rewritten.

**Build pipeline**
`registry-builder` turns `registry/` into `dist/registry/registry.json` plus `items/<id>.json`, with file contents inlined. `scripts/build-registry.mjs` then mirrors this output into `apps/docs/public/` (gitignored). `apps/docs/scripts/generate-data.mjs` then writes `apps/docs/src/generated/docs-index.json` (item metadata, CLI version, compatibility matrix) and `scripts/build-cli-docs.mjs` writes `src/generated/cli.json` from the CLI's `--help`. The deployed docs site (https://nativra.vercel.app) serves as the default remote registry.

**Packages**
- `registry-schema`: Zod schemas and types (`RegistryItem`, `SourceFile`, `RegistryManifest`).
- `registry-client`: `RegistryClient` over local or remote sources, with caching and checksums.
- `theme-engine`: semantic token model plus NativeWind CSS and StyleSheet adapters.
- `cli` (published as `nativra-cli`, bins `nativra` / `nativra-cli`; built with tsup). Commander commands are registered in `src/cli.ts`, with one file per command in `src/commands/`. Core modules:
  - `config.ts`: `nativra.json` schema (`componentsDir`/`blocksDir`/`hooksDir`/`utilsDir`/`themesDir`, `stylingTarget`, `aliasPrefix`, `aliases`, `registries`). Directories must be safe relative paths. `init` derives `aliases` from the tsconfig `paths` alias.
  - `transform.ts` / `renderFile()`: rewrites canonical `@/...` imports plus sibling `./X` imports that cross install directories. `add`, `update` and `diff` must all render through `renderFile` so they agree.
  - `client.ts`: builds sources. Remote sources must be HTTPS; `http://localhost` is the only HTTP exception.
  - `install.ts`: maps item `type` to a destination directory, then runs path-containment and symlink checks, a transactional install, and an atomic write of `nativra.lock.json`. The lockfile stores SHA-256 hashes of installed files, which `update`, `diff` and `rollback` use to detect local edits.
  - `installer.ts`: detects the package manager and installs npm dependencies with an argument array, never a shell string. Registry names and versions are re-validated against `NPM_PACKAGE_REGEX` and `SEMVER_RANGE_REGEX` first.
- `utils` (`cn`, `sha256`, …), `preview-runtime`, and `config` (shared ESLint config).

**Themes:** `theme-engine`'s `THEME_PRESETS` is the source of truth. `registry/default/themes/*/theme.ts` is generated by `pnpm themes:generate` (`scripts/generate-themes.mjs`). CI runs `--check`, so edit the engine and regenerate rather than editing those files by hand.

**Docs:** `docsPath` (`docs.mdx`, plain Markdown) is hydrated into the built item's `docs` field and rendered on `/docs/components/[id]` through `src/components/MarkdownDocs.tsx`.

**Apps**
- `apps/docs`: Vite 8 (Rolldown) + React 19 + React Router 7, Tailwind 3. Routes are in `src/App.tsx`, pages in `src/pages/`. `pnpm build` runs a client build, an SSR build of `src/entry-server.tsx`, then `scripts/prerender.mjs`, which writes static HTML for every route plus `sitemap.xml`, `robots.txt` and `404.html` into `dist/`. Item pages load full items from `public/items/<id>.json` (from disk while prerendering). Start dev servers from a `D:`-cased path on Windows: a lowercase drive letter duplicates modules.
- `apps/native-preview`: an Expo app (React 18, Babel 7). `scripts/sync-components.mjs` copies the StyleSheet source of every component, block and template, the hook and all themes from `registry/` into `components/nativra`, so the preview runs exactly what the CLI installs. On web, `?item=<id>` renders `Embed.tsx` (one item, `?theme=`, `?scheme=light|dark`, `?fixture=n`, `?layout=screen`). Demo props live in `@nativra/preview-runtime`; an item without required props in a fixture renders empty or crashes.
- **Live previews in the docs:** `apps/docs/scripts/build-preview.mjs` exports the preview app as static web (`experiments.baseUrl: "/preview"`) into `apps/docs/public/preview/` (gitignored), and item pages embed it via `src/components/PreviewFrame.tsx`. `prebuild` always re-exports; `predev` only when missing (`pnpm --filter @nativra/docs preview:build` to refresh). The docs tsconfig pins `react` types to its own React 19 because the workspace also has React 18 types.

## Conventions

- **Registry items never hard-code colors or radii.** Colors are semantic tokens (`bg-primary`, `palette.success`); radii use roles (`rounded-card` in NativeWind, `themeStyle.radius.card` in StyleSheet); shadows use `elevation()` from `use-theme-colors`. New tokens go in `theme-engine` (`SemanticColors` / `ThemeStyle`), then `pnpm themes:generate`.
- **Security hardening is deliberate.** Keep the path-traversal, symlink and HTTPS checks in the CLI when changing install, remove or rollback logic.
- **Version strings are duplicated.** The CLI's `--version` is injected from its `package.json` by tsup. A release bump must also touch:
  - every `package.json`
  - the README npm badge
  - `CHANGELOG.md`
- **Backups:** each operation that changes files writes one snapshot to `.nativra/backups/<id>/<timestamp>/` with a single `manifest.json`. `rollback` consumes the newest snapshot.
- **Vitest resolves `@nativra/*` from each package's `dist`.** After changing a dependency package, rebuild it (`pnpm turbo run build --filter=nativra-cli...`) before running the CLI tests.
- Commit messages use Conventional Commits (`feat(cli): …`, `fix(security): …`, `ci(release): …`, `chore(release): …`).
